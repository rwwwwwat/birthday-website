## 数据访问实现

使用Npgsql **10.0.3**，不使用EF Core。PostgresConnectionFactory管理单例NpgsqlDataSource，连接池最小0、最大5，短暂租用连接并异步释放；数据源构造不连接服务器。强制TLS VerifyFull，拒绝缺失凭据、多主机、Unix Socket和自定义Options，覆盖过大连接池/自动Prepare/参数日志等设置。

连接、命令与总体操作超时有边界。禁止参数日志及详细PostgreSQL错误，异常只记录类别，不记录SQL、愿望正文、连接字符串或异常对象。没有应用层连接/命令/POST自动重试；用户取消与内部超时分开处理。

PostgresWishService：验证原Content规则，参数化INSERT仅提供content及服务器固定source，WishId/CreatedAt/余数/IsRead使用数据库默认值。RETURNING取实际生成值，消耗并关闭读取器后提交事务；只有提交成功才返回结果。提交失败或不确定时抛出原DatabaseUnavailableException，由现有Controller返回503，前端原确认锁和禁止自动重发逻辑不变。

PostgresAdminWishService：

- 分页、筛选、详情、统计、标记已读沿用IAdminWishService和原响应模型。
- 筛选谓词只从true/false/null三种固定SQL中选择，用户参数均通过DbParameter传递。
- 计数与分页在同一RepeatableRead事务快照中；统计及最新完整时间也使用同一快照，避免并发写入造成计数不一致。
- 标记已读仅UPDATE is_read，并用RETURNING取得实际记录，事务提交后才返回；不存在记录仍返回null，由原接口处理404。
- 不暴露匿名愿望列表，不增加管理员账号或绕过现有认证。

PostgresDatabaseHealthProbe只执行SELECT 1，失败返回不健康，原健康HTTP200/503及Access保护保持。

## CreatedAt的UTC与100ns无损处理

已核对旧服务：SqlClient的DATETIME2读取为DateTime，原SQL服务显式指定DateTimeKind.Utc，再构造DateTimeOffset；数据库默认SYSUTCDATETIME具有UTC语义。新实现沿用API中的DateTimeOffset，不启用Npgsql旧版时间行为。

物理字段：

- `created_at timestamptz(6) NOT NULL DEFAULT clock_timestamp()`。
- `created_at_100ns_remainder smallint NOT NULL DEFAULT 0 CHECK BETWEEN 0 AND 9`。

拆分：使用UTC DateTime的Ticks计算`remainder = ticks % 10`，微秒部分保存`ticks - remainder`。重组：检查UTC、微秒对齐和余数范围，再把余数加回Ticks。因此`.1772829`保存为`.177282`及9，而不是四舍五入为`.177283`。

FromSqlServerUtc是显式入口，只对已经确认UTC语义的SQL DATETIME2指定UTC，拒绝Local DateTime，不把它当作本地时区换算。DateTimeOffset输入则按真实偏移转换为UTC。

Npgsql连接工厂初始化时关闭DateTime Infinity特殊映射，避免.NET最小值被视为-infinity；该设置只作用于当前进程，不修改系统配置。表约束同时拒绝infinity及超出.NET范围的日期。

迁移脚本要求原始UTC时间文本有完整7位小数，先在文本层分出第7位，再将6位部分转换为timestamptz；检查转换后文本完全一致，拒绝闰秒等会被数据库归一化的输入。没有通过截断整段日期或浮点时间戳降低精度。

API仍只有原五个业务字段，余数不对前端暴露。所有详情、回执、分页及统计的时间均重组。PostgreSQL新生成时间自身为微秒精度，因此其余数默认0；迁入SQL Server记录的余数按原值保留。

**排序与索引：**逻辑上仍为CreatedAt DESC、WishId DESC。由于CreatedAt现在由两列构成，两条索引的物理键均为`created_at DESC, created_at_100ns_remainder DESC, wish_id DESC`，其中未读索引增加`WHERE is_read=false`。若省略余数，同一微秒内可能按WishId错误排序，所以不能仅机械复制两个物理键。分页和最新时间查询使用同一完整顺序。

## PostgreSQL字段、约束和SQL文件

独立schema为birthday_private，不应加入Supabase Data API的exposed schemas。

| 字段 | 类型与规则 |
| --- | --- |
| wish_id | bigint GENERATED BY DEFAULT AS IDENTITY，主键，默认从1递增1 |
| content | text NOT NULL，UTF16代码单元不超过2000，保留原非空白CHECK |
| created_at | timestamptz(6) NOT NULL，clock_timestamp()，有限且在.NET时间范围 |
| created_at_100ns_remainder | smallint NOT NULL，默认0，0至9 |
| is_read | boolean NOT NULL DEFAULT false |
| source | text NOT NULL DEFAULT '王若溪大王生日网站'，UTF16长度不超过100，保留原非空白CHECK |

原CHECK确实先移除TAB/LF/CR，再去除两端ASCII空格；新表达式使用translate加指定ASCII空格的btrim再检查长度。没有用默认TRIM替代所有逻辑。原数据库规则允许NBSP等字符的情况保留；现有API的string.IsNullOrWhiteSpace更严格，未被放宽。

utf16_length函数按Unicode字符计数：BMP字符1单元，补充平面字符2单元，空串0。没有把UTF8字节长度或PostgreSQL字符长度误认为UTF16长度。PostgreSQL不接受NUL和无效Unicode，真正迁移前必须检查源数据并在异常时停止，禁止静默替换字符。

三个新SQL文件只供人工审阅，**没有对真实数据库执行**：

1. `database/postgresql/001_create_private_wishes.sql`：UTF8检查、独立schema、长度函数、六个物理字段、CHECK、主键和两个索引；撤销PUBLIC及已存在anon/authenticated角色对这些对象的权限。首次安装脚本；已有schema时直接报错并回滚，不自动替换、修复或覆盖，不声称静默幂等。
2. `database/postgresql/002_import_reviewed_wishes.sql`：无真实数据的受控导入脚本。未来独立迁移工具须通过参数化set_config在同一专用连接提供JSON及源identity信息；完整脚本在新事务中锁定目标表，要求目标为空，校验字段集合/类型、正整数ID、原始七位UTC时间及内容约束，保留原ID、正文、IsRead、Source和精度。重复/异常数据整体回滚，不执行UPDATE/DELETE或合并覆盖。
3. `database/postgresql/003_grant_runtime_permissions.sql`：未来仅给预先审查的非owner、非superuser、无BYPASSRLS的LOGIN角色授予schema/函数使用、SELECT/INSERT、UPDATE(is_read)及序列USAGE，不创建账号或密码，不授予DELETE、改正文或建表权限。仍须审核该角色已有权限和继承关系；脚本不会自动撤销其他高权限。

未来psql使用`-X -v ON_ERROR_STOP=1 -f <file>`并保留脚本内事务，禁止忽略错误或只选中片段。每份脚本使用新的独立连接；导入/角色设置由获批工具在同一连接参数化提供，不把正文、密码放在命令行。API没有任何运行脚本的入口。

序列只在目标调整，取目标最大ID、源identity计数和已有目标序列位置的最大值，避免编号重用。本机identity绝不修改。PostgreSQL的setval不随事务回滚，极端失败可能留下序列空隙；脚本不向后重置序列，迁移后必须只读复核，在全部验证完成前不开放写入。禁止通过INSERT测试序列。
